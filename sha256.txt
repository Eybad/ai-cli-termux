# sha256.txt — Hashes de tarballs por herramienta (pinning OPCIONAL)
#
# Formato:  <tool>/<tag>  <checksum>
#
# ── Rol actual ─────────────────────────────────────────────────────────────────
#
# Este archivo ya NO es la fuente obligatoria de checksums: el flujo default de
# cada herramienta obtiene el hash de forma automática y fail-closed:
#
#   opencode   → digest SHA256 del asset desde la GitHub API (release_digest)
#   agy        → SHA512 del manifest JSON de Google (manifest)
#   kiro-cli   → SHA256 del manifest.json del CDN de Amazon (manifest)
#
# Este archivo queda como capa OPCIONAL de pinning para verificaciones
# independientes del vendor o instalaciones reproducibles:
#
#   - Si existe una entrada para el tag que se está instalando, install.sh la
#     usa en lugar del digest remoto (el pin del repo gana).
#   - `--sha256 <hash>` sigue pineando un checksum explícito.
#   - Herramientas nuevas con CHECKSUM_SOURCE=hashfile siguen dependiendo de él.
#
# ── Cómo agregar un hash nuevo ──────────────────────────────────────────────────
#
#   TAG=v1.18.9
#   TOOL=opencode
#   curl -fLO "https://github.com/anomalyco/opencode/releases/download/$TAG/opencode-linux-arm64.tar.gz"
#   sha256sum opencode-linux-arm64.tar.gz
#
# Confirmá la attestation antes de agregar (requiere gh autenticado):
#
#   gh release verify-asset "$TAG" opencode-linux-arm64.tar.gz \
#     --repo anomalyco/opencode
#
# ── Notas sobre colisiones de hash ─────────────────────────────────────────────
#
# patchelf modifica el ELF después de la extracción, por lo que el hash del
# binario instalado NUNCA coincide con el del tarball. verify.sh compara el
# binario parcheado contra el hash registrado en el manifest local, NO contra
# este archivo. Este archivo cubre únicamente el tarball descargado.
#
# ── Entradas ───────────────────────────────────────────────────────────────────
