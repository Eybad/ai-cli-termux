# sha256.txt — Hashes de tarballs por herramienta
#
# Formato:  <tool>/<tag>[:<arch>]  <checksum>
#           <arch> opcional (arm64/amd64) para pins específicos de arquitectura.
#
# ── Rol actual ─────────────────────────────────────────────────────────────────
#
# OBLIGATORIO para herramientas con CHECKSUM_SOURCE=hashfile: son la única
# fuente de versión y checksum (vendor sin manifest JSON ni digest público de
# assets). Sin entrada no hay instalación (fail-closed).
#
# OPCIONAL para el resto: versión y checksum se resuelven solos de forma
# fail-closed (digest SHA256 del asset desde la GitHub API con release_digest,
# o SHA512/SHA256 del manifest JSON del vendor con manifest). Si existe una
# entrada para el tag que se está instalando, install.sh la usa en lugar del
# digest remoto (el pin del repo gana).
#
# ── Cómo agregar un hash nuevo ─────────────────────────────────────────────────
#
#   TAG=v1.18.9
#   TOOL=opencode
#   curl -fLO "https://github.com/anomalyco/opencode/releases/download/$TAG/opencode-linux-arm64.tar.gz"
#   sha256sum opencode-linux-arm64.tar.gz
#
# Confirmá la attestation antes de agregar (requiere gh autenticado):
#
#   gh attestation verify <tarball> \
#     --repo <user>/<repo> --predicate-type <predicate>
#
# Para herramientas hashfile la actualización es manual: detectar la versión
# nueva en la fuente del vendor, descargar el tarball exacto, sha256sum y
# actualizar la entrada acá.
#
# ── Notas sobre colisiones de hash ─────────────────────────────────────────────
#
# patchelf modifica el ELF después de la extracción, por lo que el hash del
# binario instalado NUNCA coincide con el del tarball. verify.sh compara el
# binario parcheado contra el hash registrado en el manifest local, NO contra
# este archivo. Este archivo cubre únicamente el tarball descargado.
#
# ── Entradas ───────────────────────────────────────────────────────────────────
